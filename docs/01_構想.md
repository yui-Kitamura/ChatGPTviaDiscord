# ChatGPTviaDiscord MVP 要件定義書

## 1. 文書の位置づけ

- 状態: 初稿・レビュー待ち。
- 目的: Discord から ChatGPT を利用するための最小構成と、その受け入れ条件を整理する。
- 現時点の README はプロジェクト名のみのため、以下の機能要件はプロジェクト名から置いた提案であり、ユーザー承認済みの仕様ではない。
- 接続方式、利用者、会話の保存方針などの未確定事項は、実装前に決定する。

## 2. 解決したい課題と MVP の到達点

Discord 上で質問を送り、同じ Discord 上で回答を受け取れるようにする。MVP では、明示的な呼び出しから回答表示までの一連の動作を、限定された利用範囲で確認できることを目標とする。

## 3. 想定する利用者・利用範囲（提案）

- 管理者: Discord 側の導入と、応答先の設定・認証情報の管理を行う。
- 利用者: 許可された Discord の場所からテキストで質問する。
- 初期検証は管理者が許可した単一サーバー・限定チャンネルで行う。
- DM 対応、複数サーバーへの一般公開は MVP の対象外とする。

## 4. 基本フロー（提案）

1. 管理者が接続に必要な設定と利用可能な場所を設定し、サービスを起動する。
2. 利用者が Discord で明示的に Bot を呼び出し、テキストを送信する。
3. Bot が利用可否と入力を確認し、処理中であることを利用者へ知らせる。
4. 採用した接続方式で質問を送り、回答を取得する。
5. Bot が質問に対応づく形で回答を Discord に表示する。
6. 失敗時は、利用者に失敗と次に取れる行動を伝える。

## 5. 機能要件（提案）

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| F-01 | 明示的なテキスト入力 | 決定した呼び出し方法で質問を受け付け、通常の会話を無差別に送信しない。空入力は送信前に案内する。 |
| F-02 | 利用範囲の制限 | 許可したサーバー・チャンネルで利用でき、許可外からの要求を外部の応答サービスへ送らない。 |
| F-03 | 質問と回答の対応 | 正常な質問に対して、送信元と対応関係が分かる位置にテキスト回答を表示する。 |
| F-04 | 長い回答の表示 | Discord のメッセージ制限を踏まえて分割等を行い、回答の末尾が黙って欠落しない。 |
| F-05 | 処理状態とエラー通知 | 処理中、タイムアウト、接続失敗、利用制限を案内する。内部の認証情報や生の例外は表示しない。 |
| F-06 | 会話の分離 | MVP は質問ごとに独立した単発応答とし、別の利用者・チャンネルの履歴が混入しない。 |
| F-07 | 過負荷の抑制 | 同時実行数・待機数・利用頻度に設定した上限を設け、超過時に案内する。具体値は実装前に決める。 |
| F-08 | 運用設定 | 接続先、モデル等の必要な設定と秘密情報をコードから分離し、必須設定が不足する場合は起動時に特定できる。 |

## 6. 非機能要件（提案）

- 認証情報を Git 管理に含めず、ログや Discord 応答にも露出させない。
- 質問本文・回答本文は既定では永続保存せず、運用ログは要求の識別子、処理結果、所要時間などに限定する。接続先サービス側の保存・送信範囲は方式決定時に確認し、利用者へ説明する。
- 応答待ちには有限のタイムアウトを設ける。無制限の再試行を行わず、二重送信・重複回答を防ぐ。
- 起動方法、必要な設定、停止方法、代表的な失敗時の確認方法を README 等へ記載する。
- 外部サービスを利用する場合は、利用量や費用の上限を管理できる運用方法を決める。

## 7. MVP の対象外（提案）

- 画像・音声・動画・添付ファイルの入力や生成。
- 複数ターンの会話履歴、永続的な記憶、履歴検索。
- Web 検索、外部ツール実行、ファイル編集、他サービスへの操作。
- 管理画面、課金機能、不特定多数への公開運用。

## 8. 実装前に決める事項

| 論点 | 決める内容 |
| --- | --- |
| ChatGPT への接続方式 | OpenAI API、既存の連携基盤など、どの経路で応答を取得するか。認証方式・利用条件・費用も合わせて確認する。 |
| Discord での呼び出し | スラッシュコマンド、メンション等から選定する。必要な Bot 権限も確定する。 |
| 対象者と場所 | 許可するサーバー・チャンネル・利用者またはロール。 |
| 応答仕様 | 使用モデル、指示文、回答の長さ、処理中表示、エラー時の文言。 |
| 制限値 | タイムアウト、同時実行数、待機数、利用頻度、利用量・費用の上限。 |
| 実行環境 | 言語、ランタイム、稼働場所、起動・再起動方法。 |
| データの扱い | 外部へ送る情報、本文保存の要否、運用ログの保存先と保持期間。 |

## 9. 完了判定

以下を満たした時点で MVP の完了とする。

- 未確定事項の決定を本文へ反映し、採用した範囲についてレビューを終えている。
- テスト用 Discord 環境から実際の接続先へ質問を送り、回答を受け取れる。
- 許可外の要求、空入力、長い回答、接続失敗、タイムアウト、利用上限を確認している。
- 複数利用者からの要求で、回答先の取り違えや会話データの混入が起きない。
- 秘密情報が追跡ファイルやログへ出ていないことを確認している。
- 第三者が手順に従って設定・起動・停止できる。

実環境で未確認の項目は未確認と記録し、文書の作成やモックでの成功だけで MVP 完了と判定しない。
